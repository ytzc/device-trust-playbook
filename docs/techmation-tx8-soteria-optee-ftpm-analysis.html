Key Takeaway / 關鍵架構定位

✓ 架構釐清： Soteria Security Subsystem 是透過 AHB memory-mapped interface 存取的硬體 IP，內建 RISC-V ibex 處理器、8KB OTP 與多種密碼加速器。OP-TEE 執行於主處理器 TrustZone Secure World，透過 Secure World-only AHB driver 存取 Soteria。Soteria 作為 Hardware Root-of-Trust、hardware-backed secure storage provider、cryptographic co-processor 與 secure boot verification anchor。

🖥 OP-TEE 執行位置

主處理器 TrustZone Secure World（不是在 Soteria 上）。Normal World 執行 Linux；Secure World 執行 OP-TEE。

🔐 Soteria 的角色

AHB-connected HW security module。由 Secure World OP-TEE driver 存取。提供：OTP key hash、Black Key、AES/HMAC/RSA/TRNG 加速器。

🔒 Bus Isolation

TZASC / PMP 設定 Soteria register region 為 Secure World-only。Normal World 無法直接存取 Soteria。

⚠ 仍待確認： TX8 主處理器是否支援 ARM TrustZone 或 RISC-V PMP；Soteria register region 是否可設定為 Secure World-only；以及 OP-TEE BSP 狀態。此文件為架構設計分析，非 TX8 實際部署確認。

Bus Isolation & Security Model / 匯流排隔離

確保 Normal World 無法直接存取 Soteria，以及 payload buffer 保護

🛡 Register Region Isolation

  • Soteria AHB Slave Port（0x00–0x60）必須設定為 Secure World-only
  • 實作機制：ARM TZASC（TrustZone Address Space Controller）或 RISC-V PMP（Physical Memory Protection）
  • Normal World 嘗試存取 Soteria region → 系統錯誤 / abort
  • OP-TEE 啟動後負責確認並維護此隔離設定
⚠ TBC： TX8 平台是否支援 TZASC / PMP 設定 Soteria region；以及此設定是否在 BSP 中預設啟用。

📦 Payload Buffer Protection

  • Soteria AHB Master Port 透過 DMA 存取 payload data
  • OP-TEE driver 必須確保 MSG3（input address）與 MSG5（output address）指向 Secure RAM
  • 禁止指向 Normal World 可讀取的記憶體
  • 操作前必須 flush data cache，確保 Soteria 讀取到最新資料
  • Critical operations（OTP access：MSG0=0x8，Debug：MSG0=0x7）需要 Magic Numbers（0x6C33B567，0x473FA4AE）
ℹ 設計原則： Soteria 的 AHB Master Port 直接存取記憶體，不經過主處理器。OP-TEE driver 的責任是確保 source / destination addresses 都在 Secure RAM 範圍內，阻止任何 Normal World 記憶體介入加密操作流程。

Integration Pillar 2：Hardware-Backed Secure Storage（HUK / Black Key）

OP-TEE Secure Storage 的加密 key（HUK）由 Soteria Black Key 機制保護，raw HUK 永不暴露在 OP-TEE RAM

🗝

Hardware Unique Key & Black Key Mechanism

Soteria TRNG 生成 key，ROK 加密後返回 Black Key，OP-TEE 不持有 raw key
1ROK 安裝：OP-TEE 呼叫 MSG0 = 0x11（INSTALL_ROK），以 ROK password 認證；Root of Key（ROK）儲存於 Soteria OTP
2Black Key 生成：OP-TEE 呼叫 MSG0 = 0x12（CREATE_BK），Soteria TRNG 生成 key，以 ROK 加密，回傳 Black Key（ENZMK + ENBK + MAC）
3OP-TEE SFS 加密/解密：OP-TEE 呼叫 MSG0 = 0x14（AES_BK），提供 Black Key + payload；Soteria 在內部解密 Black Key 並完成 AES 操作，raw HUK 永遠不進入 OP-TEE RAM
✓ 安全優勢： Black Key 機制的關鍵在於 raw HUK 永遠只存在 Soteria 內部。OP-TEE 只持有加密後的 Black Key（ENZMK + ENBK + MAC），無法還原 raw key，即使 OP-TEE Secure World 被攻破，也無法取得 raw HUK。

OP-TEE Soteria Driver Workflow

OP-TEE Secure World 中呼叫 Soteria 的標準流程

1

Interrupt Setup

啟用 Soteria 中斷（INT_EN @ 0x4C），在 OP-TEE 中為 Soteria IRQ line 註冊 secure interrupt handler

2

Busy Wait

確認 PROC_BUSY @ 0x48 為 0（idle）。Soteria 每次只能處理一個請求，需等待上一個操作完成。

3

Buffer Preparation

  • 確認 input / output buffer 在 Secure RAM
  • Flush data cache（確保 Soteria DMA 讀到最新資料）
  • 確認 MSG3（input）與 MSG5（output）指向 Secure RAM
4

Message Configuration

依序寫入 MSG0–MSG15（registers 0x00–0x3C）：

  • MSG0：命令代碼（如 0x1 AES，0x14 AES_BK）
  • MSG1：操作模式 / key size / padding
  • MSG2：data length
  • MSG3：input buffer address（Secure RAM）
  • MSG5：output buffer address（Secure RAM）
5

Trigger Execution

寫入 1 到 PROC_START @ 0x40，Soteria 內部 ibex processor 開始執行 firmware routine

6

Completion & Status Check

OP-TEE yield 或 poll，等待 Soteria IRQ。收到後讀取 INT_STATUS @ 0x50：

  • INT_STATUS[0] = 1：操作成功
  • INT_STATUS[1] = 1：操作失敗（invalid parameters）
  • INT_STATUS[2] = 1：取消操作完成
  • 寫入 1 清除對應 bit

🔑 Control Register 總覽

PROC_START @ 0x40寫 1 啟動操作
PROC_CANCEL @ 0x44寫 1 中止（BUSY=1 時）
PROC_BUSY @ 0x48讀 0=idle, 1=busy
INT_EN @ 0x4C中斷啟用設定
INT_STATUS @ 0x50[0]成功 [1]失敗 [2]取消

⚠ Security Considerations

  • Process Cancellation：寫 1 到 PROC_CANCEL @ 0x44（需 PROC_BUSY = 1）；處理 INT_STATUS[2]
  • Magic Numbers 保護：對 critical operations（Debug MSG0=0x7，OTP access MSG0=0x8），MSG3 和 MSG4 必須包含 Magic Numbers（0x6C33B567、0x473FA4AE），防止 driver bug 造成意外 OTP 操作
  • Single operation model：Soteria 每次處理一個操作，driver 必須管理 concurrency（busy wait + IRQ）
  • Secure RAM enforcement：所有 payload buffer 必須在 Secure RAM；driver 需在每次操作前驗證地址範圍

TX8 Integration Path Options / 整合路線選項

在已知 Soteria AHB 架構的基礎上，評估三條路線

ℹ 新架構資訊顯示：Soteria 透過 AHB interface 可被 OP-TEE Secure World 完整存取，因此 Path B（OP-TEE fTPM）與 Path C（Hybrid）的前提在架構上是合理的——關鍵前提仍是 TX8 主處理器是否支援 TrustZone 或等價 secure execution environment。
Path A

Soteria hRoT API Only（Primary Known Path）

不需 TrustZone / OP-TEE

直接透過 Soteria vendor API 存取所有 RoT 能力。不需要 OP-TEE。現在有了 Soteria AHB 架構，可以更明確地評估 Soteria API 涵蓋哪些 CRA-ready 能力。

優點
  • TX8 已有 Soteria，不需額外平台變更
  • 不依賴 BSP TrustZone 支援
  • Soteria 提供 AES/HMAC/RSA/TRNG + Black Key + Secure Boot
待確認
  • 需開發 custom adapter（Soteria API → TTPS DI）
  • Soteria attestation quote / PCR-like measurement 待確認
  • TPM 2.0 API compatibility 不支援
Path B

OP-TEE fTPM Only（Candidate Path）

前提：TX8 主處理器支援 TrustZone / OP-TEE

在主處理器 TrustZone Secure World 跑 OP-TEE + fTPM TA，提供標準 TPM 2.0 API。Soteria 在此路線中可作為 OP-TEE 的 secure boot anchor 與 crypto backend，即使 fTPM TA 的 persistent state 仍由 OP-TEE secure storage 管理（而非直接 Soteria）。

⚠ 前提仍待確認： TX8 主處理器型號、TrustZone 支援、BSP TF-A + OP-TEE OS 狀態。若已有 OP-TEE，則 Soteria AHB 架構已提供完整的 crypto + secure boot 支援基礎。
Path C

Hybrid：OP-TEE fTPM + Soteria-Backed Secure Storage

研究 Candidate

OP-TEE fTPM 提供 TPM 2.0 API；Soteria hRoT 透過 Black Key mechanism 提供 fTPM persistent state 的 hardware-backed key protection。新架構資訊顯示此路線在技術上是合理的方向，但仍需驗證：

  • OP-TEE fTPM TA 的 NV storage 是否可透過 OP-TEE secure storage 間接使用 Soteria Black Key 加密
  • OP-TEE secure storage driver 是否支援 Soteria 作為 custom hardware backend
  • 或：fTPM 直接呼叫 Soteria crypto API 做 key wrapping
✓ 架構合理性： Soteria 在 Secure World 可存取，且有完整 AES / Black Key API。與 OP-TEE 的整合在架構上沒有根本性阻礙，但需要驗證 OP-TEE fTPM 的 storage backend 是否支援 custom driver injection。

Recommended Position / 建議說法

繁體中文
在 Techmation TX8 情境下，若主處理器支援 OP-TEE / TrustZone 或等價 secure execution environment，Soteria hRoT 可以作為 OP-TEE 的 hardware Root-of-Trust、hardware-backed secure storage provider、cryptographic co-processor，以及 secure boot verification anchor。

English
In the Techmation TX8 context, if the main processor supports OP-TEE / TrustZone or an equivalent secure execution environment, the Soteria hRoT can serve as the hardware Root-of-Trust, hardware-backed secure storage provider, cryptographic co-processor, and secure boot verification anchor for OP-TEE.

OP-TEE does not run on Soteria; OP-TEE runs on the host processor Secure World, while Soteria is accessed through a Secure World-only AHB interface. Bus isolation (TZASC / PMP) must be configured to prevent Normal World access to the Soteria register region and crypto payload buffers.
