核心能力
Core capabilities — 四件事，一個平台
🔑

不可匯出金鑰

Hardware-rooted key

IAK / IDevID 在 TPM 2.0 內產生，fixedTPM，永不離開晶片。

📜

憑證生命週期

Certificate lifecycle

註冊 → 簽發 → 狀態 → 撤銷，全部留紀錄。CA 為 TWCA。

🧪

三項驗證

Independent checks

憑證 ↔ 鑰匙相符、設備證明持有鑰匙、憑證鏈通過。

🚫

逐台撤銷

Per-device revocation

撤銷一台不影響其他台；驗證端即時回查，fail-closed。

🚪
Trusted Access：憑證就是通行證 reference integration
服務（例如 VPN）看憑證狀態決定放不放行。OpenVPN 為目前已驗證的參考整合。

7
兩種身分方式
Two paths — 有 TPM 走硬體鑰匙，沒 TPM 走軟體憑證
🔑TPM DevID ✔ 硬體保護
  • 鑰匙在設備 TPM 內，拿不走
  • 用途硬體綁定身分、持有證明
  • CATWCA ID Center（整合中）
  • 進度實驗室已驗證
📄TWID / OpenCert 軟體憑證
  • 鑰匙在伺服器產生，受控交付
  • 用途沒有 TPM 的設備；簽發、查詢、撤銷
  • CATWCA OpenCert
  • 進度生命週期 + OpenVPN 已驗證

兩條路徑同一平台管理，但軟體憑證沒有「拿不走」的硬體保證。

Roadmap
從身分可信，走向安全維運
✔ NOW

設備身分、撤銷、VPN 存取

一台一把鑰匙；登錄、驗證、撤銷、Trusted Access。

◇ PLANNED

📦 Secure OTA

用鑰匙確認「更新給哪台」，用簽章確認「更新從哪來」。上傳成功 ≠ 更新成功。

◇ PLANNED

📡 Remote Attestation

不只證明「是誰」，還證明「狀態對不對」：TPM Quote + PCR 比對基準 → Trusted / Untrusted。

◈ ROADMAP

12
常見問題
FAQ
沒有 TPM 也能用嗎？
可以，走 TWID 軟體憑證路徑；但沒有「鑰匙拿不走」的硬體保證。
沒有正式 CA 可以先示範嗎？
可以，用 Local Demo CA 跑流程；正式導入以 TWCA 為準。
驗證通過就代表系統安全嗎？
不是。它證明「設備是誰、鑰匙對不對」；系統狀態要靠 Remote Attestation（規劃中）。
撤銷後設備會立刻斷線嗎？
已驗證的是「下一次連線被拒」；要立即切斷既有連線需另加機制。
導入後就有安全認證嗎？
不會。TTPS 提供技術能力與證據，可作為 CRA 佐證；不等於第三方認證。
TTPS 和 FideProtect 差在哪？
TTPS 管「設備是誰」（鑰匙、憑證、證據）；FideProtect 管「程式能不能在這台跑」（加密封裝、設備綁定授權，不需 TPM）。
✗ 避免說
保證 CRA 合規 · 絕對防複製 · 撤銷立即斷線 · 驗證通過＝安全
✓ 應該說
提供 CRA 技術佐證 · 鑰匙留在 TPM 複製拿不到 · 撤銷後下一次連線被拒 · 驗證證明身分與鑰匙對應
