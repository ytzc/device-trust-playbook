一句話看懂 TTPS
What TTPS is — 先知道設備是誰，再決定它能做什麼

TTPS 是設備的身分與信任管理平台。它把「設備登記 → 憑證建立與驗證 → 以憑證狀態作為存取依據」整合成一條可追蹤的管理流程。設備可以被逐台註冊、驗證、撤銷，並延伸到後續的 Remote Attestation 與 Trusted OTA。

01
📋

登記設備

Device Inventory

管理設備識別與所採用的身分方式。先建立設備紀錄，不需要立即連接 TPM。

02
🪪

建立與驗證身分

Device Identity

在設備 TPM 內產生金鑰、申請憑證，並留下可查驗的驗證結果。

03
🚪

提供存取依據

Trusted Access

讓服務依憑證狀態判斷是否允許連線；撤銷後的設備在下一次握手被拒。

✓ TTPS 是：硬體根信任的設備身分（IAK / IDevID 在 TPM 2.0 內產生）、憑證生命週期管理、驗證證據與撤銷紀錄的統一平台。
✗ TTPS 不是：第三方認證、自動符合法規的工具、商用 VPN 產品，也不等於 Remote Attestation（後者仍在規劃）。

解決什麼問題
Problems it solves — 設備連上網路，不代表身分可信
客戶面臨 · Problem

映像被複製

檔案中的憑證與金鑰，可能跟著設備映像、備份或檔案搬移一起外流；複製機難以和原機區分。

→
TTPS 做法 · Solution

保護身分金鑰

TPM 路徑讓私鑰留在 TPM 內（fixedTPM / fixedParent），複製檔案拿不到原身分金鑰。

客戶面臨 · Problem

設備需要停用

設備遺失、轉售或停止使用後，仍需要控制它後續的連線。

→
TTPS 做法 · Solution

管理身分生命週期

以憑證狀態作為存取依據；逐台撤銷後，下一次握手即被拒絕（fail-closed）。

客戶面臨 · Problem

缺少驗證依據

只看到設備在線，回答不了「身分是如何被確認的」；歐盟客戶安全問卷要求可追溯的設備識別與撤銷證據。

→
TTPS 做法 · Solution

留下可追蹤的證據

集中保留設備、憑證與驗證結果，一條指令可輸出驗證報告，便於查詢與稽核。

適用方向：工業閘道、連網機台、OT / 關鍵基礎設施與企業內網設備；實際支援條件需於導入前確認。

驗證證據：每台設備都有可查驗的證據
Verification evidence — 不只看到「已註冊」，還能確認憑證、金鑰與持有證明對得起來
MATCH

憑證與金鑰相符

SPKI match

確認憑證中的公鑰，對應設備 TPM 內的金鑰。

PASS

設備能證明持有金鑰

fresh-challenge PoP

以新的挑戰值簽章，驗證設備確實能使用該私鑰。

PASS

憑證鏈驗證通過

chain validation

確認憑證能連到本次測試信任的簽發機構。

以上為實驗室身分驗證結果（2026-09，Local Demo CA + vTPM）；不等於正式 CA 簽發完成，也不等於 Remote Attestation。負向測試（竄改、換鏈、另一 TPM）皆如預期 FAIL。

🚫 撤銷憑證，讓後續連線被拒絕 Revocation → Deny

TWID 與 OpenVPN 的參考整合，將憑證生命週期連結到存取判斷。

1
有效憑證

設備持有 TWID 憑證。

2
允許連線

驗證憑證與有效狀態（tls-verify 即時回查）。

ALLOW
3
撤銷憑證

平台更新撤銷結果。

4
拒絕再連線

下一次握手不予放行。

DENY

已驗證的是「後續握手被拒絕」，不是「立即中斷所有既有連線」。已驗證範圍為 TWID + OpenVPN（TWCA 測試環境，2026-09）；不推定 TPM-backed VPN 已完成相同整合。

◇ PLANNED

Secure OTA 安全更新

不只是遠端傳檔，而是確認更新來源、適用設備與最終結果。

  • 更新前：確認發布簽章與設備相容性
  • 更新中：套用版本政策，保留任務與事件紀錄
  • 更新後：確認版本與健康狀態，異常時受控恢復

上傳成功 ≠ 派送成功 ≠ 更新成功。設備身分金鑰用來確認目標設備，發布簽章金鑰用來確認更新來源，兩者角色不同。

◇ PLANNED

Remote Attestation 設備狀態證明

在身分驗證之外，以 TPM Quote + PCR / 參考量測值，評估被量測的系統狀態是否仍符合核准基準，判定 Trusted / Untrusted 並連動存取與更新條件。

身分驗證（現有）：設備能否證明持有對應身分的金鑰？
狀態證明（規劃）：被量測的設備狀態是否符合核准基準？
◈ ROADMAP

實體 dTPM 防複製驗證

把目前 vTPM 負向測試延伸到實體 dTPM，形成可交付的實證。可與產品整合並行。

⚙ NRE

LDevID / 客戶自有 PKI / 更多平台

依客戶既有 PKI、LDevID、自有 CA、異質平台（fTPM / 非 Ubuntu）、HA 與大量佈建需求另行工程整合。

Roadmap 為發展方向，不是已交付功能或承諾時程；下一階段的兩項能力可分階段整合。

FAQ — 用產品能力與已驗證範圍回答
沒有 TPM，也能使用嗎？
可以。平台已有 TWID 軟體憑證路徑，但它不具備 TPM 路徑相同的硬體金鑰保護；軟體私鑰是以受控的憑證包交付，可被搬移。
沒有正式 CA，可以先示範嗎？
可以。Local Demo CA 可驗證實驗室流程，但不會自動替代正式 CA，也不代表正式簽發已完成。正式導入時以 TWCA 路徑為準。
驗證通過，就代表系統一定安全嗎？
不是。現有結果主要證明設備身分與金鑰對應（憑證 ↔ 金鑰、持有證明、憑證鏈）；它不量測整個系統的軟體狀態。Remote Attestation 仍在規劃中。
導入後，產品就取得安全認證嗎？
不會。TTPS 提供技術能力與驗證證據，可作為製造商 CRA 符合性評估的佐證之一；它不等於第三方產品認證，也不代表自動符合任何法規。
撤銷之後，設備會立刻被踢下線嗎？
已驗證的是撤銷後「下一次握手被拒絕」。既有連線能否立即被終止，需要額外的連線管理機制與驗證。
TTPS 和 FideProtect 有什麼不同？
TTPS 管「設備是誰」：設備身分、憑證與驗證證據。FideProtect 管「程式能不能在這台設備執行」：執行檔加密封裝與設備綁定授權。兩者可以互補，但不是同一功能；FideProtect 不要求 TPM。
