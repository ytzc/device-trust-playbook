一句話看懂 FideProtect
What it is — 讓軟體價值，留在被授權的設備上

FideProtect 是 Application protection + device-bound licensing：保護執行檔、模型權重與設定等資產，並把執行權綁定到指定設備。檔案可以交付，授權不能任意複製。適合 Edge AI、工控與封閉網路環境。

解決什麼問題
Problems it solves — 軟體隨設備出貨，也需要一起保護
客戶面臨 · Problem

程式與模型直接交付

軟體與 AI 模型若以明文出貨，容易被逆向、分析與直接取走，核心資產難以保護。

→
FideProtect 做法 · Solution

封裝後再交付

降低明文暴露，由 Launcher 控制解密與啟動流程。

客戶面臨 · Problem

程式被複製到其他機台

已付費程式若可被複製到未授權設備執行，授權範圍失控、營收流失。

→
FideProtect 做法 · Solution

每台設備對應授權

啟動時檢查設備指紋與授權簽章，不只檢查檔案是否存在。

客戶面臨 · Problem

產線不能持續連外

產線、封閉網路與無法持續連雲的設備，依賴雲端授權服務不可行。

→
FideProtect 做法 · Solution

本機執行授權檢查

永久離線 .lic；不要求每次啟動都向雲端取得許可。

適用方向：Edge AI / 視覺檢測設備商、工控與嵌入式 Linux OEM；軟體或模型本身就是主要 IP，需要隨硬體出貨但不希望可任意複製。

保護機制：從封裝到啟動，分成三層
Protection mechanism — 先保護要交付的內容，再依授權條件決定是否允許執行
LAYER 01

加密封裝

執行檔 + 模型 / 設定等資產

交付受保護的檔案，降低明文直接可讀性。不要求修改原始碼或重新編譯。

XChaCha20-Poly1305
LAYER 02

授權檢查

設備指紋 + 授權檔 .lic

核對 .lic 簽章（Ed25519）、設備指紋與對應解密條件。每台設備一份授權。

machine-id / SoC UID
LAYER 03

記憶體內執行

Launcher 解密與啟動

在支援的執行流程中，解密內容不寫回磁碟，直接啟動。

memfd + fexecve

記憶體內執行不等於具備可信任執行環境（TEE），也不代表已防止所有執行期擷取方式；內部安全評估仍有未結案項目，持續修補中。

設備綁定：同一份程式，只有配對設備可以執行
Device binding — 將程式交付與使用權分開管理
🖥 授權設備 A
📦 受保護程式 + A 的 .lic
🧬 指紋 = A　✔ 簽章正確
✔ 設備與授權相符 → 允許啟動
⇢複製檔案
copy both files
🖥 另一台設備 B
📦 相同的受保護程式 + A 的 .lic
🧬 指紋 = B　✘ 與 .lic 不符
✘ 設備與授權不符 → 拒絕啟動（REJECTED）

🏢 站點 A · 保護程式

  1. 封裝應用與資產
  2. 準備受保護檔案
  3. 匯出簽章加密身分包
⇄安全同步身分
先同步，再各自運作

🏭 站點 B · 核發設備授權

  1. 匯入並確認站台身分
  2. 依設備指紋發出 .lic
  3. 於現場完成執行驗收
兩站共享信任身分，但 License / Machine / User 等營運資料維持各站獨立、不自動同步（設計如此）。設備在授權階段只需接觸 B 站，授權後的執行可離線。
跨站身分包屬敏感資料，需以受控方式傳遞與保管；錯 passphrase 或竄改 bundle 會被拒絕，重複匯入為 NO-OP。不是任何兩台伺服器直接互認。

常見問題
FAQ — 避免把個別測試延伸成全面保證
需要改程式或加 TPM 嗎？
支援的程式可採不改原始碼、不重編方式保護；不要求 TPM，但需做相容性驗證（Qt / QML 與讀取 /proc/self/exe 的程式已知有限制，先試裝）。
設備完全不連網也能執行嗎？
完成永久離線授權準備後可以。這不代表管理平台的安裝與升級已完全支援氣隙（air-gap）環境。
可以防止所有逆向或複製嗎？
不能作全面保證。已驗證的是指定內容封裝與授權檢查；記憶體內執行不等於 TEE，執行期安全仍持續補強，也不防合法金鑰持有者。
設備更換或程式升級怎麼辦？
需確認指紋、授權與版本相容性；重新授權規則及可回復的更新流程應在導入前定義。
FideProtect 和 TTPS 有什麼不同？
FideProtect 管「程式能否被授權使用」：加密封裝與設備綁定授權，不要求 TPM。TTPS 管「設備身分與證據」：TPM 內的私鑰、憑證與驗證紀錄。兩者可以互補，但不是同一功能。
