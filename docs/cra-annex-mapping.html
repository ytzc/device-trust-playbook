02

三階段 CRA 覆蓋範圍

不同 Phase 各自能覆蓋哪些 CRA 要求領域。

Phase 1 — Device Identity Foundation

Hardware-bound device identity + secure provisioning

  • (2)(b) Secure by default — 出廠即有 hardware-bound identity
  • (2)(d) AuthN & Identity — IDevID / LDevID cert-based auth
  • (2)(j) Attack surface — 消除預設密碼 / 臨時身份
  • Provisioning audit log — evidence readiness 基礎

Phase 2 — Key Protection & Channel Hardening

VPN/mTLS private key → hardware boundary

  • (2)(e) Data Confidentiality — hardware-protected key，breach isolation
  • (2)(k) Incident Mitigation — private key non-exportable
  • (2)(d) 延伸 — mTLS mutual auth，管理通道強化
  • Key non-extractability proof（TPM attestation）

Phase 3 — Firmware Integrity & Remote Attestation

Measured Boot + RA + SBOM + CRA evidence

  • (2)(f) Integrity — Measured Boot + PCR + attestation quote
  • (2)(l) Logging / Monitoring — attestation audit trail
  • Part II (1) SBOM — Known-Good baseline + attestation 驗證
  • (2)(c) Security Updates — post-update attestation
  • CRA Annex I evidence documentation 完整化

全程 — CRA Evidence Readiness

貫穿三個 Phase 的文件與佐證準備

  • CRA Annex I 技術控制對應文件
  • Platform security architecture 說明
  • 支援 OEM conformity assessment 的技術佐證
  • Threat model 框架提供（OEM 主導執行）
03

Gap Summary — OEM 責任範圍

這些是 FiduciaEdge 技術方案無法單獨覆蓋、需要 OEM 自行處理的 CRA 要求。

⚠ CRA 合規不等於只做 RoT： 以下 OEM 責任項目是 CRA conformity assessment 的必要條件，FiduciaEdge 無法代替 OEM 執行。
OEM 責任項目對應 CRA 要求說明
PSIRT 程序建立 Part II (2)–(6) 漏洞通報、追蹤、修補、揭露的正式程序；security contact 設置
Product Risk Assessment (1)(b) Threat model + formal risk assessment；OEM 依產品特性執行
Secure Boot 啟用 (2)(f) OEM 需在 BSP 層啟用並鎖定 Secure Boot chain
SBOM 生成 pipeline Part II (1) Build system 整合 SBOM 生成（SPDX / CycloneDX）+ OEM release key 簽署
OTA 更新 pipeline (2)(c), Part II (7)(8) 安全 firmware update 機制；簽名金鑰管理；update rollback policy
Attack surface 管理 (2)(j) 停用 JTAG/SWD in production；關閉未使用 port / service
Factory reset SOP (2)(b) 安全重置回出廠預設值的程序
Secure decommission (2)(m) 安全刪除 LDevID、私鑰、trust anchor 的流程
Conformity assessment 全部 Annex I OEM 製造商的法律責任；CE marking；自評或第三方評估
System-level log 管理 (2)(l) 非 attestation 的應用層 event log；log 保留政策；SIEM 整合
