01

PLANET Technology 背景

台灣網路設備製造商，產品線跨越多個平台架構。

公司與產品線概況

  • 台灣網路設備製造商，主要產品：Managed Switch、L2/L3 Gateway、Industrial Edge Gateway
  • 產品銷售歐洲市場 → 需符合 EU CRA 2024/2847
  • 高階 Gateway 可能落入 CRA Important Class I（Annex III）
  • Important Class I 需通過 harmonized standard 或第三方 conformity assessment
  • 平台架構多元：ARM（MediaTek）/ MIPS / 可能有 x86

FiduciaEdge 方案背景

  • FiduciaEdge 提出三階段 Remote Attestation 提案（GG2 EF1）
  • Phase 1 核心：TTPS DI 移植（Ubuntu+TPM → MTK OpenWRT + OP-TEE fTPM）
  • 目前 TTPS DI 已在 Ubuntu + hTPM 環境驗證（不是從零開發）
  • Phase 1 的主要工程工作是移植，不是全新開發
  • ⚠ 關鍵前提：MTK BSP 須已含 TF-A + OP-TEE + fTPM TA
⚠ CRA 時程壓力： 2026-09-11 漏洞通報義務生效 → 2027-12-11 CRA 全面強制執行（距今約 18 個月）。 PLANET 如屬於 Important Class I，需要及早建立 security foundation。
02

高階 ARM / MediaTek Gateway 潛力

有 TrustZone 的 ARM gateway 是三階段提案的主要目標平台。

✓ 正確說法： 問題不在於「MIPS 架構」——問題在於特定 SoC 是否有 hardware RoT。高階 ARM + MediaTek 平台若有 TrustZone 且 BSP 含 OP-TEE + fTPM TA，是三階段 RA 提案的最佳目標平台。

Device Identity & Secure Provisioning

Phase 1

  • OP-TEE fTPM TA 提供 hardware-bound key generation
  • TTPS DI 移植後，ARM gateway 可自動佈建 IDevID / LDevID
  • Hardware-bound identity：private key 在 TrustZone，Normal World 不可讀
  • TWCA certificate chain 確保 CA 主導權在 FiduciaEdge

Hardware-Bound VPN / mTLS

Phase 2

  • VPN/mTLS private key 移入 TrustZone Secure World
  • OpenSSL TPM2 Provider / PKCS#11 bridge 整合 StrongSwan / OpenVPN
  • 即使 OS root 被入侵，key 仍不可提取
  • 對應 CRA Annex I (2)(e) Data Confidentiality

Firmware Integrity & Remote Attestation

Phase 3

  • Measured Boot：BL2→BL32→Linux 每階段 hash extend 至 fTPM PCR
  • RA Client 產生 signed attestation report
  • NMS Verifier 比對 Known-Good SBOM baseline
  • Pass/Fail/Unknown policy → 管理存取控制
⚠ ARM BSP 前置條件（PLANET 端）： MTK BSP 須含 TF-A（BL1/BL2/BL31）+ OP-TEE OS（BL32）+ fTPM TA，且 Secure Boot 已啟用。 這是 Phase 1 的阻擋條件，FiduciaEdge 無法單方面解決。
03

Legacy MIPS Switch / Bridge 的限制

沒有 hardware RoT 的平台，能力有限但仍有可做的事。

常見誤解： 「MIPS 做不到」— 正確說法是「缺乏 hardware RoT 的 MIPS SoC 做不到 hardware-bound identity 和 Remote Attestation」。如果可以加入 external hRoT 或 SE，仍有可行路徑。

沒有 hardware RoT 時的限制

  • 無法提供 hardware-bound device identity（只能做軟體金鑰，可被複製）
  • 無法提供 non-exportable private key
  • 無 Measured Boot / PCR-like registers → 無法提供 Remote Attestation evidence
  • CRA-ready 程度有限，只能提供補償控制
  • 可以做：Gap analysis + signed firmware update + mTLS（軟體金鑰）+ CVD policy

External hRoT / SE 可行路徑

  • 先做 feasibility study：評估 MIPS SoC 是否能加入 external hRoT 或 SE
  • 若有 External SE + PKCS#11 介面：Phase 1（hardware-bound identity）仍可行
  • Phase 2（key protection）透過 PKCS#11 也可行
  • Phase 3（Measured Boot + RA）需另確認 SE 是否有 measurement 能力（通常不支援）
  • 需確認：SE 型號、介面相容性（I2C / SPI / USB）、BOM cost impact
建議客戶說法： 「PLANET 的 MIPS 產品線，我們建議先進行 feasibility study，評估是否能加入 external secure element。若可行，Phase 1/2 仍能建立 hardware-bound identity 與 key protection。若不可行，我們提供 CRA gap analysis 與補償控制建議，協助 PLANET 了解差距並優先強化高風險項目。」
04

三階段 Remote Attestation 提案（GG2 EF1）

針對 ARM + MediaTek gateway 的三個 Phase。時程為工程任務循序總和，許多可並行。

Phase 1 — 安全身份佈建 [10w]

Hardware-Bound Device Identity via OP-TEE fTPM
  • TTPS DI 移植：Ubuntu+TPM → MTK OpenWRT + OP-TEE fTPM
  • fTPM TA 部署 + TSS2 stack 整合
  • TWCA Device Identity Provisioning CLI [4w]
  • Hardware-bound IDevID / LDevID 佈建
  • Initialize HRoT on ARM TrustZone [6w]
阻擋條件： MTK BSP 含 TF-A（未設定 +3w Lead Time）・硬體樣品
Out of Scope：整合 PLANET 客製 BSP 分支（~3w）、GUI 管理介面

Phase 2 — 硬體綁定 VPN 強化 [9w]

Hardware-Bound VPN/mTLS Key Protection
  • TrustZone Crypto Key & Engine Offloading [4w]
  • OpenSSL TPM2 Provider / PKCS#11 橋接 VPN 引擎
  • mTLS Isolation Verification & Testing [2w]
  • Network Bandwidth & Crypto Benchmarking [3w]
阻擋條件： Phase 1 完成・VPN 技術選定（StrongSwan / OpenVPN）
Out of Scope：OpenWRT nftables / VLAN 網路切片（PLANET 負責）

Phase 3 — Remote Attestation [25w]

Measured Boot + RA + NMS Policy + CRA Evidence
  • Measured Boot Instrumentation BL2→BL32 [8w]
  • OpenWRT Kernel Runtime Integrity [3w]
  • Attestation Client & Challenge Protocol [8w]
  • Standalone Attestor Service + web UI [6w]
  • NMS Verifier + Known-Good Baseline DB
  • Policy Engine：Pass / Fail / Unknown
前置（PLANET 端）：Phase 1/2 完成・Secure Boot 設定・SBOM pipeline・NMS API
Out of Scope：PLANET CI/CD SBOM 簽署管線（FE 提供規格指導）
05

對 PLANET 的 Customer-facing Positioning

如何向 PLANET 正確說明我們的方案價值與邊界。

ARM Gateway — 強力定位

  • FiduciaEdge 提供 CRA-Ready Device Trust & Platform Security Solution
  • 三階段方案直接對應 CRA Annex I (2)(d)(e)(f)
  • 基於 ARM TrustZone 的 hardware RoT，提供業界認可的安全隔離
  • 相比軟體方案，hardware-bound key 和 attestation 可信度更強
  • Phase 1 移植既有驗證方案（不是從零開發），降低技術風險
  • 支援 CRA conformity assessment 的技術 evidence 準備

MIPS / 舊型號 — 誠實說明

  • 先提供 CRA Gap Analysis，讓 PLANET 了解目前差距
  • 評估 external SE 可行性後，說明 Phase 1/2 的可能路徑
  • 建議 PLANET 識別高風險 / 高出貨量型號，優先升級
  • MIPS 平台可做：SBOM、signed firmware update、mTLS（軟體金鑰）
  • CRA 2027 deadline → 硬體改版的窗口有限，需要及早決策
  • 若 PLANET 決定不升級，提供 compensating controls 作為過渡

✓ 正確說法
