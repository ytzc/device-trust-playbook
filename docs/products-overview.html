🪪 TTPS
這台設備是誰？
  • 🔑
    保護什麼

  • 😈
    防什麼

  • 🖥
    需要什麼
    TPM 2.0、Ubuntu x86_64、自架平台、TWCA

🔒 FideProtect
這份程式能不能在這台跑？
  • 📦
    保護什麼
    程式、AI 模型、設定檔等軟體資產
  • 🕵️

  • ⚙
    怎麼做
    加密封裝 → 綁設備指紋 → 本機離線檢查 → 記憶體內執行
  • 📴
    拿來做什麼
    軟體隨設備出貨、封閉網路產線、Edge AI 模型保護
  • 🖥
    需要什麼
    Linux ELF、x86_64 或已驗證 ARM；不需 TPM、不改碼

回答的問題這台設備是誰？身分怎麼確認？這份程式能不能在這台執行？
保護對象設備身分：鑰匙、憑證、驗證證據軟體資產：執行檔、模型、設定
核心機制TPM 內產鑰匙 · CA 簽發 · 三項驗證 · 逐台撤銷XChaCha20-Poly1305 封裝 · 設備指紋 · per-device .lic · 記憶體內執行
硬體需求TPM 2.0（另有 TWID 軟體憑證路徑）不需 TPM；machine-id 或 SoC UID
連線需求設備與平台 / CA / VPN 需連線授權後永久離線
設備端要裝tpm-agent + ttpsctl不裝常駐程式；受保護檔 + .lic
已驗證平台Ubuntu 24.04 x86_64 + TPM 2.0（vTPM）x86_64 Ubuntu / Debian、Techmation TX8
撤銷 / 收回平台撤銷，下一次連線被拒永久授權無法遠端收回；重新授權規則另定
下一階段Secure OTA · Remote Attestation · 實體 dTPMAdmin Web 登入 · 可靠升級 · 錯誤報告匯出
認證狀態兩者皆提供技術證據，可作 CRA 佐證；目前均無第三方產品認證

一起用：設備可信，程式受控
Better together — 互補，不重疊

兩者目前是各自獨立的產品，沒有共用元件；「一起用」指在同一台設備上同時部署，不是已整合的單一方案。

→ 兩者一起用
常見誤會：FideProtect 不需要 TPM，也不是 TTPS 的一部分；TTPS 不保護程式內容，只保護設備身分。
共同邊界：兩者提供技術能力與證據，不等於第三方認證，也不自動符合法規。
